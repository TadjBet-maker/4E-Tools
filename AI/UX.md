# 4E Tools --- UX SPEC v2.4

## Status

Splash, Login и главный пользовательский экран --- **LOCKED**. Их нельзя
перерабатывать без нового решения в DECISIONS.

Пользовательские строки MVP хранятся централизованно в `src/strings/`
(D-026).

## Branding

Брендинг регулируется D-027. Visual source of truth должен находиться в
`assets/branding/`. До добавления финальных ассетов этот документ
фиксирует структуру и поведение, но не pixel-perfect геометрию.

## Общий стиль

Mobile-first. 4E Tools. Премиальный, практичный строительный интерфейс.
Тёплый золотисто-бронзовый акцент. После авторизации: Dark/Light с
одинаковой UX-структурой.

## Splash --- LOCKED

-   Всегда фирменная тёмная тема.
-   Логотип 4E Tools.
-   Утверждённый короткий бренд-текст/девиз.
-   Проверка/восстановление сессии.
-   Валидная сессия → приложение.
-   Нет сессии → Login.
-   Не показывать каталог или выбор склада.

## Login --- LOCKED

-   Всегда фирменная тёмная тема.
-   Логотип/4E Tools.
-   Поле «Логин».
-   Поле «Пароль».
-   Кнопка «Войти».
-   «Забыли пароль?» → «Обратитесь к администратору».
-   Иконка настроек → unauth Settings.
-   Информационные элементы: «Учёт», «Контроль», «Команда».
-   Технический email `<login>@4e.local` никогда не показывается
    пользователю.

### Auth error texts

-   Неверный логин/пароль: **«Неверный логин или пароль»**
-   Inactive account: **«Учётная запись отключена. Обратитесь к
    администратору»**
-   Нет сети: **«Нет соединения. Проверьте интернет»**
-   Backend/Supabase временно недоступен: **«Сервис временно недоступен.
    Повторите позже»**

Во время login request кнопка не должна отправлять повторный запрос.

## Settings без авторизации --- LOCKED

Разрешены только: - «О приложении»; - версия приложения.

Тема здесь не показывается. Splash/Login всегда тёмные. Переключение
Dark/Light доступно только после успешной авторизации. Доступа к
доменным данным без сессии нет.

## Главный экран --- LOCKED

Порядок: 1. Верхняя зона: 4E Tools + пользователь/профиль. 2. Поиск. 3.
«Мои инструменты». 4. Заголовок каталога. 5. Визуальная сетка категорий.
6. Нижняя навигация.

Запрещён рекламный баннер «Надёжный инструмент для больших результатов».
После login нет обязательного выбора склада.

## «Мои инструменты»

MVP показывает текущие закреплённые экземпляры. Срока возврата и
рабочего таба «Просроченные» нет.

## Каталог

Категория → модели → физические экземпляры с доступностью и складом.

## Экземпляр

Показывает: - модель; - отображаемый inventory number; - статус; -
склад/состояние, когда применимо.

AVAILABLE → основное действие «Забрать инструмент».

Admin может дополнительно видеть: - serial_number; - purchase_date; -
note.

REPAIR отображается как «На ремонте» без фиктивного склада «Сервис».

## TAKE

-   явное подтверждение;
-   loading;
-   double-tap protection;
-   server RPC;
-   success только после подтверждения backend;
-   при конфликте показать недоступность и обновить данные.

## RETURN

«Мои инструменты» → экземпляр → «Вернуть» → склад →
«Исправен»/«Повреждён» → комментарий при повреждении → подтверждение.

Success только после server response.

## Data states

Каждый data-driven экран: - loading; - error + retry; - empty; - normal.

## Offline

Можно показывать уже имеющиеся in-memory данные. Persistent server-state
cache не входит в MVP (D-037). TAKE/RETURN не ставятся в скрытую offline
queue и не показываются успешными без сервера.

## Brigadier UX

Бригадир видит текущие назначения и разрешённую историю сотрудников,
которые **сейчас** состоят в его бригаде (D-034). Историческое членство
отдельно не визуализируется.

## Admin

Mobile-first dashboard: - инструменты; - модели; - сотрудники/бригады; -
склады; - ремонт; - списание; - история; - настройки.

Создание модели и экземпляра использует серверную автоматическую
нумерацию; admin не вводит `inventory_group` или `slot` вручную.

## History visibility

-   Employee: только собственная история операций.
-   Brigadier: история операций пользователей, которые сейчас входят в
    его бригаду (D-034).
-   Admin: полная история экземпляра инструмента и административная
    история.
-   Отдельного employee/brigadier экрана полного жизненного цикла
    инструмента в MVP нет (D-039).
