# 4E Tools --- PROJECT

## Продукт

4E Tools --- Android-first мобильное приложение небольшой строительной
компании для учёта физических экземпляров инструмента.

## MVP

Сотрудник входит в приложение, видит каталог, находит конкретный
экземпляр, забирает его, видит его в «Мои инструменты» и возвращает на
выбранный склад. Администратор управляет инструментами, сотрудниками,
складами, повреждениями и историей. Бригадир видит инструменты своей
бригады.

## Стек

-   React Native + Expo + TypeScript strict
-   Expo Router
-   Supabase Auth + PostgreSQL
-   TanStack Query для server state
-   React Context + design tokens + AsyncStorage для темы
-   Jest + React Native Testing Library
-   SQL/RPC integration tests для критических операций

## Авторизация

Пользователь входит по `login + password`. Внутри auth-слоя login
преобразуется в технический email `<login>@4e.local` для Supabase Auth.
Технический email в UI не показывается. Самостоятельного сброса пароля в
MVP нет.

## Локализация

MVP только на русском; строки централизованы в `src/strings/`.

## Роли

`employee`, `brigadier`, `admin`.

## Основные статусы

`AVAILABLE`, `ASSIGNED`, `DAMAGED`, `REPAIR`, `WRITTEN_OFF`. `LOST` ---
post-MVP.

## Инвентаризация

Модель/группа имеет номер, например `1`. Физические экземпляры: `1.1`,
`1.2`, `1.3`. Внутренний UUID всегда отдельный.

## Offline

Чтение ранее загруженных данных может кэшироваться. TAKE/RETURN в MVP
требуют серверного подтверждения. При отсутствии сети кнопка не создаёт
ложного успеха: UI показывает, что операция недоступна без соединения, и
предлагает повторить после восстановления сети.

## Безопасность

Клиент содержит только публичные Supabase URL/anon key. Service-role key
никогда не поставляется в приложение. Доступ контролируется RLS и
серверными RPC.

## Первая цель

Получить рабочую Android test build, пройти реальный сценарий: login →
каталог → экземпляр → TAKE → мои инструменты → RETURN → история.

## Брендинг

Брендинг регулируется D-027 и UX.md. Визуальные исходники хранятся в
`assets/branding/`. Splash/Login используют LOCKED тёмный бренд-стиль;
после входа доступна Dark/Light тема.

## Нумерация моделей и экземпляров

`tool_models.inventory_group` создаётся сервером через
`create_tool_model` (D-036). `tools.slot` создаётся сервером через
`create_tool` (D-032). Клиент не генерирует эти значения самостоятельно.

## Server-state cache

Persistent offline cache для TanStack Query не входит в MVP (D-037).

## История и идемпотентность

Все mutating RPC фиксируют событие в `movements`, включая создание
моделей и экземпляров (D-038). Полный жизненный цикл инструмента
доступен только admin (D-039).
